Исправлено в версии 1.0.0.75 (Windows и Linux) по последнему комментарию («Теперь наверное нужны пояснения… ConfiguratorAuth напрочь отсутствует… не могу добраться до раздельной авторизации»):

1. **Токены раздельной авторизации — секция «Авторизация».** В диалоге «Выбрать…» появилась секция **«Авторизация»** с токенами `%enterpriseauth.user%`/`%enterpriseauth.password%`/`%enterpriseauth.mode%` и `%configuratorauth.user%`/`%configuratorauth.password%`/`%configuratorauth.mode%` (плюс русские алиасы `%авторизацияпредприятия.…%`/`%авторизацияконфигуратора.…%` и плоские `%enterpriseuser%`/`%enterprisepassword%`/`%configuratoruser%`/`%configuratorpassword%`) ([`ScriptParameterResolver.cs`](Workspace1C/Services/ScriptParameterResolver.cs), [`ScriptScenarioEditViewModel.cs`](Workspace1C/ViewModels/ScriptScenarioEditViewModel.cs)). Если раздельная авторизация не задана или дефолтная («Запрос») — токен подставляется пустым: фактически используется авторизация базы/общая.
2. **Пояснения к полям в диалоге «Выбрать…».** У каждого поля теперь есть человекочитаемое описание — что означает значение и откуда оно берётся (в т.ч. для `%connection.user%`: «логин из настроек базы; пуст — подставляется решённый логин общей/раздельной авторизации»); поиск идёт и по описанию ([`ScriptTokenPickerViewModel.cs`](Workspace1C/ViewModels/ScriptTokenPickerViewModel.cs), окно выбора WPF/Avalonia).
3. **Стабилизирован кэш каталогов платформ.** Устранена гонка параллельного доступа к TTL-кэшу каталогов установленных платформ — тест `PlatformVersionCacheTests` больше не флакает ([`PlatformVersionService.cs`](Workspace1C/Services/PlatformVersionService.cs)).

Покрыто тестами `ScriptParameterResolverTests` (ключи `enterpriseauth.*`/`configuratorauth.*`: заполненные, дефолтные, null; решённые креды не перезаписывают заданные раздельные), `ScriptTokenPickerViewModelTests` (секция «Авторизация» присутствует, у каждого ключа непустое описание, поиск по описанию), `PlatformVersionCacheTests`, `OneCPlatformLocatorPlatformVersionTests`.
