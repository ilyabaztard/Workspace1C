Исправлено в версии 1.0.0.71 (Windows и Linux): команды Telegram-бота теперь принимаются из темы/подгруппы канала. Раньше сообщение из темы приходило с `chat.id` канала (например `-100…`) и `message_thread_id` темы, но разбор апдейтов ([`TelegramBotCommandService.ParseUpdates`](Workspace1C/Services/TelegramBotCommandService.cs:208)) брал только `chat.id`, а разрешение чата сравнивало сырые строки (`AllowedChats` + `allowed.Contains`) — команда из темы настроенного чата отклонялась как «команда из неразрешённого чата».

Что изменено:

- Запись `TelegramCommand` расширена полем `MessageThreadId` ([`TelegramBotCommandService.cs`](Workspace1C/Services/TelegramBotCommandService.cs:33)); `ParseUpdates` извлекает `message_thread_id` из сообщения (строки 230–235), у обычных сообщений без темы значение `null`.
- Добавлена чистая функция разрешения чата [`IsAllowedChat`](Workspace1C/Services/TelegramBotCommandService.cs:151): кандидаты — значения `AllowedChatIds` (разделители «,», «;», пробел) или, при пустом списке, чат уведомлений; каждый кандидат нормализуется через [`TelegramNotificationChannel.ParseChatTarget`](Workspace1C/Services/TelegramNotificationChannel.cs:80) (в т.ч. ссылка `t.me/c/<id>[/<thread>]` → `-100…` + тема) и сравнивается числовым сравнением [`SameChatId`](Workspace1C/Services/TelegramNotificationChannel.cs:135). Настройка без темы разрешает весь чат (основной чат и любые темы); настройка с темой — только указанную тему.
- [`LoopAsync`](Workspace1C/Services/TelegramBotCommandService.cs:105) использует `IsAllowedChat(settings, channel.TelegramChatId, command.ChatId, command.MessageThreadId)`, а ответ отправляется обратно в ту же тему: приватный `SendAsync` передаёт `message_thread_id` в метод `sendMessage` ([`TelegramBotCommandService.cs`](Workspace1C/Services/TelegramBotCommandService.cs:325), строки 333–335). В `TelegramBotApiClient.SendMessageAsync` поддержка `message_thread_id` уже была ([`TelegramBotApiClient.cs`](Workspace1C/Services/TelegramBotApiClient.cs:48)).
- `AllowedChats(...)` оставлен без изменений (обратная совместимость), основной путь — новая функция.
- Локализация ru/en: добавлен ключ-подсказка `Bot.AllowedChatsHint` (можно указывать ссылку вида `t.me/c/1234567890/1234` — команды будут приниматься из указанной темы) и она выводится в окне «Команды Telegram-бота» (WPF [`TelegramBotWindow.cs`](Workspace1C/Views/TelegramBotWindow.cs:32) и Avalonia [`TelegramBotWindow.Avalonia.cs`](Workspace1C/Views/TelegramBotWindow.Avalonia.cs:41)).

Добавлены юнит-тесты ([`TelegramBotCommandServiceTests.cs`](Workspace1C.Tests/TelegramBotCommandServiceTests.cs)): извлечение `message_thread_id` из апдейта темы и `null` для обычного сообщения, разрешение чата из ссылки с темой при совпадающей теме и отклонение другой темы, настройка без темы разрешает любые темы и основной чат, fallback на чат уведомлений, числовое сравнение chat_id по значению.

Реализовано на обеих платформах.
