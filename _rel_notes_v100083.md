# Workspace 1C 1.0.0.83

Релиз доступен для **Windows** (WPF) и **Linux** (Avalonia).
Скачать: https://github.com/sivatorov/Workspace1C/releases/tag/v1.0.0.83

### Добавлено

- **Пользователи информационных баз (меню «Утилиты» → «Операции» →
  «Пользователи информационных баз…», Windows)** — новое окно управления
  пользователями ИБ без конфигуратора. Слева — список баз с отметками и поиском,
  справа — пользователи выбранной базы (имя, полное имя, способ входа, признак
  пароля, пользователь ОС) и форма пользователя. Пакетные операции выполняются по
  очереди во всех отмеченных базах со статусом по каждой базе и журналом:
  **«Создать / изменить»** (полное имя, пароль, аутентификация 1С и ОС, пользователь
  ОС `\\ДОМЕН\Пользователь`, показ в списке выбора, роли — добавить к имеющимся или
  заменить; роли, которых нет в конфигурации, перечисляются в журнале),
  **«Сменить пароль»**, **«Отключить вход»** (снимает аутентификацию 1С и ОС и
  скрывает из списка выбора — удобно для уволенных сотрудников) и **«Удалить»**.
  Кнопка «Роли выбранного → в форму» копирует набор ролей пользователя-образца,
  под формой показывается перечень ролей конфигурации. Подключение — COM-коннектор с
  учётными данными «Конфигуратора» базы (с учётом общей авторизации); подтверждение
  запрашивается один раз на операцию. На Linux COM-коннектора 1С нет — окно
  открывается с пояснением, операции недоступны
  ([`InfobaseUsersService.cs`](Workspace1C/Services/InfobaseUsersService.cs),
  [`InfobaseUserInfo.cs`](Workspace1C/Models/InfobaseUserInfo.cs),
  [`InfobaseUsersViewModel.cs`](Workspace1C/ViewModels/InfobaseUsersViewModel.cs),
  [`InfobaseUsersWindow.cs`](Workspace1C/Views/InfobaseUsersWindow.cs),
  [`InfobaseUsersWindow.Avalonia.cs`](Workspace1C/Views/InfobaseUsersWindow.Avalonia.cs),
  [`UtilitiesMenuCatalog.cs`](Workspace1C/Services/UtilitiesMenuCatalog.cs)).
- **Общий механизм COM-операций во внешнем процессе** — `ComScriptRunner` выполняет
  операции объектной модели 1С в отдельном процессе Windows PowerShell 5.1 (под
  .NET Framework вызов `Connect` у comcntr.dll работает штатно, а сбой или зависание
  базы не трогают приложение). Скрипт передаётся ключом `-EncodedCommand`, строка
  подключения с паролем — только через stdin, ответ — Base64(JSON) в stdout; пароли
  маскируются в текстах ошибок; при отсутствии 64-битного коннектора запрос
  автоматически повторяется в 32-битном PowerShell. Механизм будет использоваться и
  следующими функциями (регламентные задания ИБ)
  ([`ComScriptRunner.cs`](Workspace1C/Services/ComScriptRunner.cs)).
- **Релизный workflow: новость в Telegram-канал** — после публикации релиза шаг
  «Новость в Telegram» отправляет текст `_telegram_msg_v<версия>.txt` в канал
  проекта, если в репозитории задан секрет `TELEGRAM_BOT_TOKEN`
  ([`release.yml`](.github/workflows/release.yml)).

Покрыто тестами `InfobaseUsersServiceTests` (+22): протокол и маскирование секретов,
разбор ответа (в т.ч. «развёрнутых» массивов PowerShell), параметры и проверки формы,
логика окна, пункт меню; на Windows — реальный запуск PowerShell с несуществующим
ProgID (проверка синтаксиса скрипта и протокола stdin/stdout).

Подробности — в [CHANGELOG.md](https://github.com/sivatorov/Workspace1C/blob/main/CHANGELOG.md).
