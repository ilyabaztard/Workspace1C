Исправлено в версии 1.0.0.99 (Windows и Linux) по комментарию от 27.10 («Во время обработки 2-й, которой нет в сервере СУБД — показывает данные первой базы … во время начала обработки 3-й — была надпись 2-й, и в конце появилась 3-я»):

1. **В прогрессе больше нет сдвига на предыдущую базу** — строка «N из M: <база>» пересобирается при смене имени и счётчика. Причина сдвига была в оповещениях: `CurrentBaseName`/`ProcessedCount` не поднимали событие `ProgressText` (окна WPF и Avalonia подписаны именно на него и читают составную строку по смене счётчика), поэтому при обработке следующей базы отображалось имя предыдущей. Теперь имя обрабатываемой базы и счётчик «N из M» показывают текущую базу для каждой итерации — первая, вторая (в т.ч. с ошибкой «нет в сервере СУБД»), третья ([`ClusterMigrationViewModel.cs`](Workspace1C/ViewModels/ClusterMigrationViewModel.cs), общий ViewModel для обеих платформ).

2. Покрыто тестами `ClusterMigrationViewModelTests` (+1: `Migrate_Progress_ShowsEachBaseNameInTurn_IncludingFailedSecond` — в оповещениях прогресса имя КАЖДОЙ базы по очереди, включая вторую с ошибкой; без исправления окно получало «2 из 3: База1» / «3 из 3: База2»).
